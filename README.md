# Система учёта туристических туров (Вариант 16)

Консольное приложение для ведения каталога туров с поиском по ключевым словам. Разработано в рамках лабораторной работы по порождающим паттернам проектирования (Creational Patterns).

## Сущности предметной области

По условию варианта система поддерживает два типа туров:
1. **Пляжный тур (`BeachTour`)** — помимо базовых параметров (название, страна, дни) хранит тип пляжа (`песок` или `галечный`).
2. **Экскурсионный тур (`ExcursionTour`)** — хранит количество запланированных экскурсий (целое число $\ge 1$).

---

## Структура файлов

Проект разбит на независимые модули:

* `interfaces.py` — абстрактные интерфейсы сущностей (`ITour`), репозитория (`ITourRepository`), фабрик (`ITourAbstractFactory`) и команд (`ICommand`).
* `models.py` — классы `BeachTour` и `ExcursionTour`. Реализуют клонирование (`clone`) и сериализацию в словарь (`to_dict`).
* `validators.py` — классы проверки полей: непустая строка, положительное число, корректность страны, тип пляжа, число экскурсий.
* `factories.py` — фабрики создания туров и реестр `TourFactoryRegistry`.
* `storage.py` — работа с файлом `countries.json` и репозиторий `LazyJsonTourRepository` с ленивой инициализацией.
* `menu.py` — реализация команд (`ICommand`), элементов меню и класса сборки `MenuBuilder`.
* `main.py` — точка входа: выбор режима работы с БД, сборка зависимостей и запуск меню.
* `countries.json` — справочник стран для валидации.

---

## Применённые паттерны проектирования

### 1. Фабричный метод (Factory Method) и Абстрактная фабрика (Abstract Factory)
* **Интерфейс:** `ITourAbstractFactory` в `interfaces.py`.
* **Реализации:** `BeachTourFactory` и `ExcursionTourFactory` в `factories.py`.
* **Как работает:** фабрика объединяет создание тура (`create_tour`) и создание специфичного для него валидатора (`create_specific_validator`). Для пляжного тура создаётся `BeachTypeValidator`, для экскурсионного — `ExcursionsCountValidator`.
* **Реестр (`TourFactoryRegistry`):** связывает текстовые ключи (например, `"1"`, `"пляжный"`) с фабриками. Чтобы добавить новый тип тура (например, горнолыжный), достаточно написать один класс фабрики и зарегистрировать его в реестре, не трогая код меню.

### 2. Строитель (Builder) и Команда (Command)
* **Команда (`ICommand`):** каждое действие меню оформлено отдельным классом с методом `execute()` (`AddTourCommand`, `ShowToursCommand`, `SearchEgyptCommand`, `CloneTourCommand`, `CloseDbCommand`, `ExitCommand`).
* **Строитель (`MenuBuilder`):** собирает меню по цепочке через методы `.set_title(...)` и `.add_item(...)`. Метод `.build()` проверяет наличие обязательной команды выхода и возвращает готовый объект `Menu`.

### 3. Ленивая инициализация (Lazy Initialization)
* **Класс:** `LazyJsonTourRepository` в `storage.py`.
* **Как работает:** при создании объекта файл на диске не открывается. Метод `_ensure_initialized()` проверяет дескриптор и открывает файл только тогда, когда программа впервые пытается прочитать (`get_all`) или записать (`add`) данные. Дескриптор остаётся открытым до вызова команды явного закрытия (`close_db`).

### 4. Прототип (Prototype)
* **Метод:** `.clone()` в интерфейсе `ITour` и классах `BeachTour`, `ExcursionTour`.
* **Как работает:** создаёт независимый экземпляр тура с копированием всех значений полей. В команде `CloneTourCommand` пользователю предлагается изменить любое поле; при нажатии клавиши Enter сохраняется старое значение.

## Режимы работы базы данных

При старте программа предлагает три варианта:
1. `[1] Создать новую БД` — создаёт пустой JSON-файл с указанным именем (по умолчанию `tours.json`).
2. `[2] Открыть существующую БД` — открывает существующий JSON-файл и считывает сохранённые туры при первом обращении.
3. `[3] Работать в памяти` — хранит туры только в RAM текущего сеанса, файл на диске не создаётся.

Файл остаётся открытым на протяжении сеанса. Закрыть его и сбросить буфер на диск можно через пункт меню `[5] Закрыть файл базы данных` либо при штатном выходе через `[0]`.

## Запуск приложения

Требуется Python 3.10 или выше. Дополнительных сторонних библиотек не требуется (используются только стандартные модули `json`, `os`, `enum`, `abc`).

```bash
python main.py
Пример сценария проверки

    1. Запустить main.py, выбрать режим 1, нажать Enter (создастся tours.json).

    2. Нажать 1 («Добавить новый тур»), заполнить поля (по умолчанию предлагаются тур в Египет, 7 дней, песок).

    3. Нажать 4 («Клонировать и редактировать тур»), выбрать тур 1. На полях названия и страны нажать Enter, на поле дней   ввести 14. 
        Будет создан новый тур с изменённым сроком и сохранёнными остальными полями.

    4. Нажать 3 («Поиск туров со словом 'Египет'») — отобразятся оба тура.

    5. Нажать 5 («Закрыть файл базы данных») — файл на диске закроется с сохранением состояния.

    6. Нажать 0 для выхода.
```
